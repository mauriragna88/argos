# Design Principles — Vivi's Permanent Design Foundation

Part of Vivi's design pipeline: `vivi-design-principles` (always first) → `vivi-motion-design` (when applicable) → `vivi-visual-qa` (last). Vivi loads these automatically.

## Purpose

This is Vivi's permanent visual design foundation.

This skill MUST be used as a reference for every significant frontend project.

Vivi must NOT wait for the user to explicitly request this skill.

Whenever Vivi creates, redesigns, restructures or significantly modifies:

- websites
- landing pages
- SaaS interfaces
- dashboards
- web applications
- marketing pages
- product pages
- business websites
- portals
- interactive interfaces

this skill MUST be considered first.

This skill defines HOW Vivi thinks about visual design. It does not force every website to look identical.

The objective is:

CONSISTENT DESIGN QUALITY + UNIQUE BRAND EXPRESSION

## 01 — The Three Fundamental Principles

Every design must be guided by:

LAYERING · SPACING · RESTRAINT

### Layering

Avoid visually flat interfaces.

Create visual depth using:

- foreground
- midground
- background
- typography
- imagery
- cards
- overlapping elements
- shadows
- z-index
- visual planes
- scale
- contrast
- perspective

Layering should establish hierarchy.

Do not add layers simply because they look impressive.

Every layer should have a purpose.

### Spacing

Whitespace is an active design element.

Use:

- generous section spacing
- intentional margins
- consistent padding
- controlled content width
- vertical rhythm
- grouping
- separation

Do not fill empty space simply because it exists.

Empty space can communicate:

- importance
- luxury
- calm
- hierarchy
- focus

### Restraint

Premium design is not the accumulation of effects.

Avoid unnecessary:

- gradients
- shadows
- glassmorphism
- rounded cards
- 3D objects
- animations
- decorative elements
- floating elements
- visual noise

If an element does not improve:

- communication
- hierarchy
- usability
- storytelling
- brand identity

consider removing it.

STUDY → UNDERSTAND → ABSTRACT → RECOMBINE → CREATE ORIGINAL DESIGN

## 03 — Reference Analysis

When the user provides:

- screenshot
- website
- video
- image
- competitor
- design reference
- Awwwards example
- Godly.design example
- 21st.dev example
- Motion reference

analyze it before implementation.

Identify:

1. Composition
2. Visual hierarchy
3. Typography
4. Spacing
5. Color
6. Grid
7. Layering
8. Imagery
9. Interaction
10. Motion
11. Storytelling
12. Visual rhythm

Then ask internally:

WHAT MAKES THIS DESIGN EFFECTIVE?

Do not ask:

HOW CAN I COPY THIS?

The final implementation must be original.

## 04 — Visual Hierarchy

Every page must have clear hierarchy.

The user should quickly understand:

WHAT IS THIS?

WHO IS IT FOR?

WHY DOES IT MATTER?

WHAT SHOULD I DO NEXT?

Use:

- display typography
- supporting typography
- labels
- CTAs
- visual anchors
- imagery
- contrast
- scale

Not every element should have equal visual importance.

## 05 — Typography

Typography is a structural component.

Prefer:

- strong display typography
- readable body typography
- clear hierarchy
- controlled line length
- appropriate contrast
- editorial combinations when appropriate

Avoid:

- too many font families
- tiny body text
- excessive font weights
- decorative fonts everywhere
- poor line-height
- awkward wrapping

Headlines should feel intentional.

Typography must work on mobile.

## 06 — Color System

Choose colors according to:

- brand
- audience
- industry
- emotional objective
- accessibility

Prefer:

- neutral foundation
- primary brand color
- one or two controlled accents
- strong contrast

Do not use gradients simply because they are fashionable.

Do not force a universal palette onto every client.

## 07 — Layout

Do not automatically use:

NAVBAR → HERO → 3 CARDS → FEATURES → TESTIMONIALS → CTA → FOOTER

unless this structure makes sense.

Think about:

STORY → INFORMATION → EXPERIENCE → ACTION

Possible layouts:

- editorial
- asymmetric
- modular
- full-width
- constrained
- overlapping
- horizontal
- split-screen
- immersive

Choose based on the project.

## 08 — Hero Sections

A hero must communicate:

WHAT · VALUE · AUDIENCE · ACTION

Possible techniques:

- oversized typography
- layered imagery
- cinematic photography
- product mockups
- editorial composition
- visual depth
- subtle motion
- strong CTA hierarchy

Avoid generic SaaS hero templates.

## 09 — Component Design

Components should be:

- reusable
- configurable
- accessible
- consistent
- maintainable

Typical components:

Hero · Section · CTA · Card · FeatureGrid · CaseStudy · ProductShowcase · Testimonial · Navigation · Footer

Motion-specific components belong to `vivi-motion-design`.

## 10 — Brand Adaptation

Every project must have its own visual identity.

Determine:

- brand personality
- audience
- industry
- tone
- colors
- typography
- imagery
- visual density

Do not make every website look like a DEVOGATEC website.

### DEVOGATEC Default Direction

When creating DEVOGATEC materials, prefer:

- deep navy
- blue
- cyan
- white
- controlled orange/gold accents

Personality:

- technology
- trust
- growth
- professional
- local
- human
- modern

Avoid:

- cyberpunk
- gaming aesthetics
- crypto aesthetics
- neon overload
- generic AI startup aesthetics

## 11 — Anti-Template Test

Before finalizing ask:

Does this look like a template?

Could this belong to any random company?

Does the brand feel distinctive?

Could the design exist without the brand and still look identical?

If YES:

Improve the art direction.

## 12 — Design Before Code

Before significant implementation determine:

PROJECT · AUDIENCE · OBJECTIVE · BRAND · VISUAL LANGUAGE · CONTENT HIERARCHY · LAYOUT · RESPONSIVE STRATEGY

Then build.

Do not blindly generate components.

## 13 — Mobile-First Thinking

Mobile is not desktop reduced in size.

Consider mobile during design.

Check:

- typography
- spacing
- navigation
- imagery
- cards
- CTA
- content order
- interactions

Every desktop design decision must have a mobile strategy.

## 14 — Accessibility

Design must consider:

- readable contrast
- semantic structure
- keyboard navigation
- focus states
- readable typography
- accessible controls
- reduced motion

Accessibility is part of quality.

## 15 — Premium Design Definition

Never interpret:

"premium" · "modern" · "beautiful" · "amazing"

as:

"add more effects."

Instead translate them into:

- better hierarchy
- better typography
- better spacing
- better imagery
- stronger composition
- meaningful interaction
- visual restraint
- consistency
- storytelling

## 16 — Final Design Principle

The strongest design is intentional.

Do not ask:

"How many effects can I add?"

Ask:

"What deserves the user's attention?"

Design what matters. Remove what does not.
